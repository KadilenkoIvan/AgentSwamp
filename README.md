# AgentsSwarm — рой ИИ-агентов поверх Radmin VPN

Несколько ИИ-агентов (Claude Code, Codex, OpenCode, любой другой CLI-агент) на разных компьютерах
вместе работают над одним git-репозиторием: распределяют роли, обсуждают идеи в общем чате,
берут задачи с доски, коммитят и подтягивают коммиты друг друга. Человек может в любой момент
написать в чат и скорректировать работу.

```
        Radmin VPN (26.x.x.x)
┌──────────── ХОСТ ─────────────┐          ┌──────── ДРУГ ────────┐
│ python swarm.py hub           │  HTTP    │ python swarm.py ...  │
│  • чат / цель / роли / задачи │◄────────►│ агент (Codex и т.п.) │
│  • git-репозиторий (origin)   │  :8765   │ workspaces/<имя>/    │
│  • веб-чат http://localhost:8765         └──────────────────────┘
│ агент хоста (Claude Code)     │
└───────────────────────────────┘
```

Всё в одном файле `swarm.py`, нужен только **Python 3.8+** и **Git**. Сторонних библиотек нет.
Интерфейс для агентов — обычные shell-команды (`python swarm.py send/inbox/wait/task ...`)
поверх HTTP API, поэтому подходит любой агент, который умеет запускать команды в терминале.

---

## 1. Хост (тот, у кого запущен хаб)

1. **Radmin VPN**: создай сеть, дай друзьям её имя и пароль. Твой IP в Radmin начинается с `26.`.
2. **Открой порт 8765** в брандмауэре Windows (PowerShell от администратора, один раз):
   ```powershell
   netsh advfirewall firewall add rule name="AgentsSwarm" dir=in action=allow protocol=TCP localport=8765
   ```
3. **Запусти хаб** (в папке с `swarm.py`; на Windows вместо `python` может быть `py`):
   ```bash
   python swarm.py hub --key ПРИДУМАЙ_ПАРОЛЬ --goal "Что нужно сделать"
   ```
   - взять за основу существующий проект: добавь `--repo-from C:\путь\к\проекту` (или URL на GitHub);
   - иначе создаётся пустой репозиторий с README;
   - хаб напечатает адрес для друзей, например `http://26.12.34.56:8765/`.
4. **Веб-чат**: открой <http://localhost:8765> — там чат с агентами, цель (можно менять),
   список агентов с ролями (можно переназначить роль / лидера) и доска задач.
   Пиши туда — для агентов твои сообщения имеют наивысший приоритет.
5. **Свой агент**: подключи как обычного участника (шаг 2 ниже) с `--hub http://localhost:8765`.

Результат работы лежит в `hub-data/repos/project.git` — `git clone hub-data/repos/project.git`
или просто смотри в свою рабочую папку `workspaces/<имя>` после `git pull`.

## 2. Участник (друг, или агент самого хоста)

1. Подключись к сети в Radmin VPN.
2. Скачай `swarm.py` с хаба (или склонируй этот репозиторий):
   ```bash
   curl -o swarm.py http://26.12.34.56:8765/swarm.py
   ```
3. Зарегистрируйся — будет создана рабочая папка `workspaces/<имя>` с клоном проекта:
   ```bash
   python swarm.py setup --hub http://26.12.34.56:8765 --name petya-codex --key ПАРОЛЬ --kind codex
   ```
   Имя — латиница/цифры/`_.-`, уникальное для каждого агента.
4. Запусти агента **внутри** `workspaces/<имя>` одним из способов:

   **а) Интерактивно** (видишь, что агент делает, можешь вмешаться). Открой Claude Code / Codex /
   OpenCode в этой папке и напиши ему:
   > Read .git/swarm-prompt.md and follow it. Start now.

   Агент сам будет читать чат (`wait`), брать задачи, коммитить и пушить.
   Если он остановился — напиши «продолжай по протоколу».

   **б) Автономно** (раннер сам перезапускает агента при новых сообщениях/задачах):
   ```bash
   cd workspaces/petya-codex
   python ../../swarm.py run --agent claude      # или --agent codex / --agent opencode
   python ../../swarm.py run --cmd "my-agent --prompt-file {prompt_file}"   # любой другой CLI
   ```
   Промпт подаётся агенту в stdin, либо путь к файлу подставляется вместо `{prompt_file}`.
   ⚠️ Пресеты запускают агентов **без подтверждений** (`--dangerously-skip-permissions` и аналоги),
   иначе они не смогут работать без человека. Используй на машине/папке, где это допустимо.

## 3. Как агенты договариваются

- **Лидер** — первый подключившийся агент (если он пропадёт на 15 мин, лидером станет следующий;
  в веб-чате можно назначить вручную).
- Лидер ждёт, пока подключатся остальные (~3 минуты или пока человек не напишет «start»),
  читает их представления, **раздаёт роли** (архитектор, бэкенд, тестер/ревьюер…)
  и **разбивает цель на задачи** на доске.
- Остальные представляются, получают роли и задачи, могут предлагать идеи.
- Работа: `git pull --rebase` → правки → коммит `[имя] #задача: ...` → `git push` →
  `task done`. Хаб сам рассылает всем уведомление «X pushed to main: …», остальные подтягивают коммиты.
- Сообщения людей (из веб-чата или `swarm.py chat`) — приоритетнее любого плана.

Полный текст инструкции для агентов: `python swarm.py protocol`.

## 4. Шпаргалка команд

Запускать из рабочей папки агента (настройки берутся из `.git/swarm.json`):

| команда | что делает |
|---|---|
| `status` | цель, лидер, агенты и роли, задачи |
| `inbox` / `wait [--timeout 60]` | новые сообщения сразу / с ожиданием |
| `send "текст" [--to имя]` | написать всем / одному |
| `history [-n 30]` | вся история чата |
| `tasks [--all]` | доска задач |
| `task add "название" [--desc ...] [--to имя]` | создать задачу |
| `task claim/done/block/open ID [--note ...]` | взять / завершить / заблокировать / вернуть |
| `task assign ID имя`, `task note ID "текст"` | переназначить / комментарий |
| `role имя "роль"`, `lead имя`, `goal "текст"` | роли, лидер, цель |
| `chat --name ivan` | чат в терминале для человека (альтернатива веб-чату) |

Любой параметр можно указать явно: `python swarm.py status --hub http://26.x.x.x:8765 --key ПАРОЛЬ --name ivan`.

## 5. HTTP API (для своих интеграций)

Все `/api/*` требуют заголовок `X-Swarm-Key` (с localhost — не требуется). JSON на входе и выходе.

| метод и путь | тело / параметры |
|---|---|
| `GET /api/state` | цель, лидер, агенты, задачи |
| `POST /api/join` | `{name, kind}` |
| `POST /api/send` | `{from, to, text}` (`to: "*"` — всем) |
| `GET /api/inbox?name=&wait=60` | новые сообщения агента (long-poll), сдвигает курсор |
| `GET /api/messages?since=0` | вся лента |
| `POST /api/goal` / `role` / `lead` | `{by, text}` / `{by, agent, role}` / `{by, agent}` |
| `GET/POST /api/tasks` | `{by, title, desc, assignee}` |
| `POST /api/tasks/<id>` | `{by, action: claim\|done\|block\|open\|assign\|note, assignee, note}` |
| `/git/project.git` | git remote (Basic auth: имя / ключ) |

## 6. Если что-то не работает

- `cannot reach hub` — проверь, что хаб запущен, Radmin подключён (`ping 26.x.x.x`), порт открыт в брандмауэре хоста.
- `unauthorized` / `Authentication failed` — неверный `--key`.
- Агент «уснул» в интерактивном режиме — напиши ему «продолжай: swarm wait и работа по протоколу», или используй режим `run`.
- Конфликты git — агенты решают их сами через `git pull --rebase`; лидер делит задачи по файлам, чтобы конфликтов было меньше.
- Отладка хаба: переменная окружения `SWARM_DEBUG=1`.
